# Flutter verification — Phase 1.1

## Reproducible environment

`.github/workflows/flutter.yml` supports unfiltered `push`, `pull_request`, and
`workflow_dispatch` events. It runs on Ubuntu 24.04 with:

- Flutter **3.38.5**, stable, pinned explicitly; no floating stable SDK selection.
- Dart **3.10.4**, bundled with that SDK; the version step asserts both versions.
- Temurin Java **17** for Android Gradle Plugin 8.11.1 and Gradle 8.14.
- Android command-line tools 16.0 (archive 12266719), platform 36, Build Tools 35.0.0 and
  NDK 28.2.13676358 (matching the pinned Flutter Android configuration).
- Third-party actions pinned to commit SHAs; Node 24-based checkout v5, Java v5, artifact-upload v6 and Android-setup v4
  are used to avoid obsolete action runtimes.

`pubspec.lock` was generated by the pinned SDK on a GitHub runner, not authored by
hand. The CI job has read-only repository permissions, disables persisted checkout
credentials, has a 40-minute timeout and cannot commit formatter changes. No
repository settings/secrets, runtime dependencies or business architecture changed.
Hosted runner images, Java 17 security patches and Android command-line tools can
still receive updates; this is not a bit-for-bit hermetic build environment.

## Gates, in order

1. Verify Flutter/Dart versions and print Java version.
2. Run `python3 tool/verify_scaffold.py` before Flutter creates ephemeral files.
3. Run `flutter pub get --enforce-lockfile`; reject a modified lockfile.
4. Run `dart format --output=none --set-exit-if-changed lib test`.
5. Run `flutter analyze --no-pub`.
6. Run `flutter test --no-pub --reporter expanded --timeout 2m`, including the
   customer repository, validation, synchronization, export and UI regressions.
   Run a separate Chrome test for IndexedDB close/reopen persistence.
7. Run `flutter build web --release --no-pub`.
8. Set up Android tools and explicitly install the required SDK/NDK packages.
9. Run `flutter build apk --debug --no-pub`.
10. Upload Web and APK outputs as `web-and-android-debug` (7-day retention).

Version JSON and dependency lockfile are retained as `verification-inputs`
(14-day retention), including on a failed run. No test gate uses
`continue-on-error`, failure masking or relaxed assertions. A failed gate stops
subsequent verification; a configuration change alone is not a passing result.

## Observed failure and correction

The first enhanced run
[41452143700](https://github.com/RamezBadry85/Target/actions/runs/41452143700)
passed SDK-version verification, structural checks and dependency resolution, then
failed `dart format --set-exit-if-changed lib test` with exit code 1. The root cause
was unformatted source from Phase 1, when no local SDK was available. Analysis,
tests and builds were skipped in this run, not passed.

A temporary, branch-scoped push workflow ran Flutter 3.38.5 to format the source
and generate `pubspec.lock`. It succeeded in run
[41452492778](https://github.com/RamezBadry85/Target/actions/runs/41452492778)
and committed `6b05c2d`. That workflow was then removed. The permanent workflow
remains read-only. No tests, assertions or functionality were removed.

The original Phase 1 workflow also eventually succeeded in run
[41451390531](https://github.com/RamezBadry85/Target/actions/runs/41451390531),
but it lacked the formatting gate and does not establish Phase 1.1 completion.
The delivery response provides the final full-verification run URL and actual
step results for the delivered revision.

## Android setup failure and correction

Run [41452746834](https://github.com/RamezBadry85/Target/actions/runs/41452746834)
passed version checks, locked dependencies, formatting, analysis, tests and Web,
but failed before the Android build. The setup action's default package list
included the obsolete `tools` package. Exact failure:

```text
[command]/usr/local/lib/android/sdk/cmdline-tools/16.0/bin/sdkmanager tools
Warning: Failed to find package 'tools'
Error: The process '/usr/local/lib/android/sdk/cmdline-tools/16.0/bin/sdkmanager' failed with exit code 1
```

Temporary read-only diagnostics retrieved and sanitized the runner log through
GitHub check annotations because artifact/log storage is inaccessible from this
sandbox. Evidence is available in run
[41453836707](https://github.com/RamezBadry85/Target/actions/runs/41453836707).
Those diagnostics and their extra `actions: read` permission were then removed.
Intermediate diagnostic attempts also failed (log archive/ANSI handling); they
are not passing verification runs.

The permanent workflow now pins Android setup v4, explicitly requests only
`platform-tools`, pins command-line tools 16.0, and still installs the required
platform/build-tools/NDK packages before building the APK. No Android build gate
was removed or ignored. Upload-artifact was also updated to Node 24-based v6.

## Running and inspecting CI

```sh
# Authenticated GitHub CLI, with Actions dispatch permission:
gh workflow run flutter.yml --ref arena/e27dac95-target
gh run list --branch arena/e27dac95-target
gh run view RUN_ID
gh run watch RUN_ID --exit-status
```

You can also use **Actions → Flutter foundation → Run workflow** in GitHub and
select this branch, if your account has permission. During this session the
integration rejected manual dispatch with HTTP 403 (`Resource not accessible by
integration`); push-triggered runs executed. Manual dispatch and PR events are
configured but their execution is not claimed as tested. No permission/settings
changes were made to bypass this restriction.

## Limits of these checks

This sandbox still lacks Flutter/Dart and cannot fetch GitHub artifact/log storage
hosts (although the GitHub API and git work). CI step outcomes are inspected via
the Actions API. Build outputs and complete logs remain available in GitHub.
No local build or device/emulator launch is claimed.

Web release and Android debug builds do not verify Windows, iOS or macOS, nor do
they establish store/release signing, manual accessibility or visual acceptance.
Those native hosts and manual checks remain part of the platform acceptance plan
in `VERIFICATION.md`.
